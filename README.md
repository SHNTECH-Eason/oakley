# Oaklay 汪汪好習慣救援隊

把實體的貼紙作息表搬到手機／平板上：完成一項就點一下蓋爪印，網頁記住所有歷史紀錄並累積點數，多台裝置即時同步。

原本的 A4 列印海報留在 `kids_routine_poster (5).html`，這個 App 沿用它的配色、注音與汪汪隊風格，讓小朋友一眼認得出是同一張表。

---

## 目前有什麼

| 分頁 | 內容 |
|---|---|
| **今天** | 8 個作息項目，點一下蓋爪印（有動畫、音效、震動回饋）。全部完成會跳慶祝畫面 |
| **挑戰** | 50 關的數學闖關地圖，十題全對才解鎖下一關，每天最多前進三關 |
| **獎勵** | 作息表以外的好表現，家長另外給爪印。八個預設理由，也可以改理由和點數 |
| **本週** | 海報那張 8×7 的格子表，加上總爪印／連續全破天數／打卡天數 |
| **家長** | 補登、編輯作息項目、點數規則、多裝置同步、備份匯出入、版本與更新 |

前兩個分頁是小朋友實際會用的，所以排在一起；後面三個是給大人看的。

規則：

- 小朋友**只能打卡當天**，過去的日子要補登得走家長模式，避免一次把整週點完
- 每完成一項 = 1 個爪印，當天全部完成再加 5 個（可在家長模式調整）
- **每個項目可以指定星期幾出現。** 家長分頁 →「作息項目」，每一項下面都有一到日的勾選。預設就有兩個例子：「出門上學」只勾一到五，「完成功課」只勾星期二。週末不會跑出「出門上學」，也不會因此算成沒完成。要做「週三才有的才藝課」「週末才有的整理房間」都是勾一勾的事
- 已經蓋過的爪印永久有效，就算之後把那個項目刪掉也不會被扣回去
- 特別獎勵不綁在任何一天的項目上，獨立計算，也不影響「當天全部完成」的判定

### 挑戰（數學闖關）

50 關的路徑地圖，每關十題加減選擇題，**十題全對才能解鎖下一關**。難度沿路爬升：

| 關卡 | 題型 | 例 |
|---|---|---|
| 1–10 | 10 以內加法（附爪印圖示輔助數數） | 3 + 4 |
| 11–20 | 10 以內加減 | 8 − 3 |
| 21–30 | 20 以內加減 | 15 − 7 |
| 31–40 | 兩位數不進位 | 23 + 15 |
| 41–50 | 兩位數進位借位 | 27 + 18 |

地圖上節點左右交錯排成一條路，中間用小爪印當足跡。已通過的關卡有星星、目前這關會呼吸發光、後面的上鎖。打開時自動捲到現在這關。

**幾個刻意的設計：**

- **全對才過關，但沒過可以立刻重來。** 要證明真的會了不是矇對，但不會被卡一整天 —— 重試會重新出題
- **每天最多前進三關。** 有節制才有得期待，也避免一個下午把 50 關刷完。已通過的關卡可以無限重玩，不計獎勵也不推進
- **從第 1 關開始，不是從兩位數開始。** 五歲直接算 27+18 會挫折，而挫折會把整個 App「我好棒」的情緒基調弄壞
- **選擇題不是輸入框。** 五歲打字慢，而且輸入框會讓答錯變成「我連怎麼回答都不會」。錯誤選項刻意貼近正確答案（差 1、差 2，兩位數關卡再加上差 10），亂數選項一眼就能排除等於沒在算
- **答錯不用紅叉叉。** 直接把正確答案標出來，說「下次一定可以」
- **當天第一次挑戰就給 2 個爪印，答錯也拿得到；每過一關 +4。** 一天上限 14，壓在作息全破（13）附近 —— 作息表才是主線，闖關是加分的娛樂

家長模式可以直接跳關（太簡單或太難時用）。常數都在 [js/quiz.js](js/quiz.js) 最上面，出題規則在同一個檔案的 `makeQuestion`。

### 為什麼拿掉了月曆熱區圖

原本「紀錄」分頁有一張整月的完成度月曆。拿掉的原因是實際使用上**作息幾乎天天 100%** —— 大人是等事情真的做完了才把手機遞過去，這張表不是在量測，是一個儀式。所以整張月曆會是同一個顏色，它回答不了「我該注意什麼」，只是把你本來就知道的事再畫一次。

真正有變化的資料是闖關進度：關卡會前進、答對率會變。**那才是回頭看會覺得「他真的長大了」的東西**，所以那個分頁改成放闖關地圖，地圖本身就是一份成長紀錄。

### 特別獎勵

自己收玩具、幫忙做家事、有禮貌、勇敢嘗試、主動看書、自己吃飯、願意分享、特別棒 —— 八個預設理由，點下去會跳確認視窗，理由和點數都可以現場改再給。

**刻意要按兩次才給得出去。** 這個分頁小朋友也點得到，一鍵發放的話他會自己給自己一百個爪印，整套制度就沒意義了。確認視窗是給家長按的。

給錯了可以在下方的紀錄裡收回。

預設清單目前寫死在 [js/app.js](js/app.js) 的 `REWARDS`。之後若要讓家長自訂，把它搬進 Store 就會跟著同步。

## 使用者是五歲小孩，這件事決定了很多設計

他沒有自己的手機，是大人在某一項完成後把手機遞過去讓他點一下再收回。所以：

- **除了「今天」那一頁，其他分頁都是給大人看的。** 週檢視、統計、家長模式他不會去看
- **他的整個體驗就是點下去那一刻。** 反饋做得好不好，等於這個 App 成不成立

由此推導出來的幾個決定：

**已完成再點不會取消，只會再放一次慶祝。** 五歲小孩會因為好玩再戳一次自己剛蓋的章，如果那會取消，他就親手把爪印刪掉了。要取消請走家長模式的補登。

**家長分頁沒有密碼保護。** 一開始做了 PIN，後來拿掉了：小孩是被大人遞過手機點一下就還回去，根本不會自己翻分頁，鎖起來擋到的其實是家長自己 —— 每次補登都要輸入，切走分頁還會自動上鎖。真正危險的只有「清除所有紀錄」，那個本來就有兩層確認。

**反饋必須有變化。** 一天八次、連續幾個月，一模一樣的動畫一個禮拜就變壁紙。所以稱讚語隨機、音高隨進度爬升、粒子數量隨進度加大，另外有約 1/3 機率觸發金色的驚喜效果。

**天天會出來稱讚他。** 完成一項時天天從右下角彈出來揮手、眨眼，帶一個對話泡泡說出稱讚語（有注音），約兩秒後自己退場。給特別獎勵時會放大一號、停久一點。

**全部完成時她會展翼起飛。** 一天只有一次，值得比揮手更大的動作 —— 慶祝畫面的天天會張開飛行翼衝出來，然後停在飛行姿勢上下浮動。動作分級是刻意的：完成一項是揮手，全破才是起飛。

角色圖是 `pointer-events: none`，不會擋到任何按鈕；系統開了「減少動態效果」時停在第一格不播放。

### 動畫素材怎麼來的

兩張精靈圖，都是每格 200×200 的正方格，用 CSS `steps()` 播放，不需要影片解碼也不依賴任何函式庫：

| 檔案 | 內容 | 格數 | 大小 |
|---|---|---|---|
| `assets/skye-cheer.webp` | 揮手＋眨眼，循環播放 | 18 | 163KB |
| `assets/skye-fly.webp` | 展翼起飛，播一次後停在飛行姿勢 | 15 | 87KB |

來源是一支綠幕 MP4，處理流程全部在瀏覽器裡完成（這台沒有 ffmpeg）：

1. 逐格解碼，用「綠度 = G − max(R,B)」判定去背 —— 比固定門檻更能抓到深綠的陰影，中間帶做 alpha 漸變讓邊緣不鋸齒，並壓掉角色身上的綠溢色
2. 取所有畫格的**聯集邊界**當統一裁切框，角色才不會逐格忽大忽小
3. 挑出可用的段落，以 12fps 取格
4. 合成正方形格子、置中、輸出 WebP

**只播一次的動畫要用 `steps(格數 - 1)`。** `steps()` 預設是 `end`，動畫結束的瞬間會再往前跳一格 —— 用 `steps(15)` 跑 15 格的圖，最後會停在第 16 格也就是空白處。起飛那張是 `steps(14)` 跑到 `-14` 格，才會停在最後一格的飛行姿勢上。循環播放的就沒這個問題（會直接繞回第一格）。

WebP 而不是 PNG 的理由：同樣的內容 PNG 要 981KB，**WebP 只要 163KB**，差六倍。iOS 14 起全面支援。

要換素材或加別的角色，給一支**綠幕影片**就好，格式規格見上面的流程。`assets/marshall.png` 目前沒有用到，等有毛毛的動畫素材時可以比照辦理。

**稱讚偶爾會叫名字。** 「Oaklay 好厲害！」對五歲小孩的份量比通用的稱讚重得多。但刻意只有約四成會叫 —— 每次都叫就變成口頭禪，偶爾出現才有「這是在跟我說話」的感覺。當天全部完成那一句一定會叫名字，因為一天只有一次。

名字取自家長模式設定的暱稱。中文名直接接（「禹欣好棒！」），英文名會自動補空格（「Oaklay 好棒！」）。

**反饋要累進。** 第八次應該比第一次盛大：粒子從 12 增到 26、音高往上爬五個半音、只剩一項時跳出「只剩最後一個囉！」並讓那張卡發光、全破放紙屑雨。

**語音朗讀（預設關閉）。** 五歲還不太識字，聽得懂比看得懂有用。開啟後只念一句稱讚（「好棒喔！」），用 `speechSynthesis` 的 zh-TW 語音。

刻意**不念項目名稱** —— 大人本來就在旁邊，小孩知道自己剛做完什麼，念一長串「滴眼藥水、噴鼻子、睡覺，完成！」反而拖慢那一刻的節奏。

預設關閉是因為合成語音有機械感，而且睡前那一項會出聲。開關在家長模式的「點數規則」裡。

## 本機預覽

這台電腦沒有 node 也沒有 python，所以附了一個 PowerShell 寫的靜態伺服器：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080
```

然後開 <http://localhost:8080/>。

> 不能直接用檔案總管點開 `index.html`。`file://` 下 Service Worker 不能註冊、ES module 也會被 CORS 擋掉。

想用同網段的手機測試（需要系統管理員權限的 PowerShell）：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080 -Lan
```

## Firebase 設定（多裝置同步）

程式碼已經寫好了，但 Firebase 主控台那邊還有三個開關要打開。到 <https://console.firebase.google.com/project/oakley-d414f> ：

**1. 啟用匿名登入**

Authentication → 開始使用 → Sign-in method → 選「匿名」→ 啟用。

沒開這個會看到 `auth/configuration-not-found`。

**2. 建立 Firestore 資料庫**

Firestore Database → 建立資料庫 → 位置選 **asia-east1（台灣）** → 先選正式版模式。

**3. 貼上安全規則**

Firestore Database → 規則 → 把 `firestore.rules` 的內容整份貼上 → 發布。

沒做這步會看到 `permission-denied`。

設定好之後重新整理網頁，家長模式的「多裝置同步」會變成綠燈「已同步」。

### 怎麼配對第二台裝置

最快的方式是**分享邀請連結**：家長模式 → 多裝置同步 → 「📤 分享邀請連結」。手機上會叫出系統分享面板（可以直接丟 LINE），電腦上則複製到剪貼簿。

對方點開連結會跳出確認視窗，按「加入」就完成，不用手動輸入 16 碼。

也可以走手動：複製配對碼 → 在另一台的家長模式貼上 → 加入。

家長 PIN 故意不同步，每台裝置各自設定。

### 兩種加入方式的差別

|  | 合併本機紀錄 | 用途 |
|---|---|---|
| **邀請連結** | 預設**不**合併（可勾選） | 分享給別人看／用 |
| **手動輸入配對碼** | 一律合併 | 配對自己的第二台裝置 |

差別的理由：手動輸入通常是在配對自己的另一台裝置，兩邊都是同一個小孩，取聯集才不會弄丟爪印。但邀請連結是給別人的 —— 如果對方原本有自己的紀錄，合併會把他的資料污染到你家裡去，所以預設只接收。

換組之前會把舊的配對碼存起來，並顯示在同步區塊裡。萬一加錯了，把它貼回去就能回到原本的資料。

### 邀請連結的安全性

配對碼放在網址的 `#` 片段而不是查詢字串，因為 `#` 後面的內容**不會送到伺服器**，不會留在 GitHub Pages 的存取紀錄或 referrer 裡。App 一讀到就立刻用 `history.replaceState` 把它從網址列抹掉，避免被書籤或截圖留存。

但這串等同鑰匙：**拿到連結的人可以看也可以改**這份紀錄。沒有唯讀模式。

### 分享空白連結

同一個區塊的「分享空白連結」給的是純網址。對方點開因為瀏覽器裡沒有配對碼，App 會自動幫他產生一組新的 —— 拿到的是全新的空白作息表，跟你們家完全無關。

## 部署（GitHub Pages）

程式全部是靜態檔案，沒有建置流程，push 上去就會自動更新。

repo 的 Settings → Pages → Source 選 **Deploy from a branch**，Branch 選 `main` / `/ (root)`，存檔後網址是：

```
https://shntech-eason.github.io/oakley/
```

注意網址帶了 `/oakley/` 子路徑，所以專案裡**所有路徑都必須是相對路徑**（Service Worker 註冊、manifest 的 `start_url` 和 `scope`、快取清單都是）。改程式時不要改成 `/css/styles.css` 這種絕對路徑，會在子路徑下 404。

根目錄的 `.nojekyll` 是必要的，不放的話 GitHub Pages 會用 Jekyll 處理檔案。

部署後記得到 Firebase 主控台 → Authentication → Settings → **Authorized domains** 加入 `shntech-eason.github.io`。

### 這是公開 repo

所以做了兩件事：

- 程式碼裡**不寫孩子的真實姓名**，只有暱稱。全名要填的話存在雲端設定，那份不進版控
- `assets/` 裡的汪汪隊角色圖是 Spin Master 的著作，自家使用沒問題，但這是有意識做的取捨，不是沒注意到

用手機瀏覽器開網址：

- **iPhone Safari**：分享 → 加入主畫面

加完會有自己的圖示、全螢幕開啟、離線也能用。

### 更新怎麼傳到裝置上

push 之後 GitHub Pages 會自動重新部署，裝置端則是這樣運作：

1. 使用者下次打開 App（或切回前景）時，Service Worker 會去檢查有沒有新版
2. 有的話新版**先在旁邊裝好但不接手** —— 不能在小朋友打卡打到一半時把整個 App 換掉
3. 畫面下方跳出「🎉 有新版本了」，按下去才切換並自動重新載入

家長模式的「版本與更新」會顯示**目前實際在服務這個頁面的版本號**（例如 `v12`）。那個數字是直接跟 Service Worker 本人要來的，不是寫死在畫面上的字串 —— 所以看到什麼就真的是什麼，不會有「以為更新了其實沒有」。

同一個區塊還有：

- **檢查更新** — 手動觸發檢查
- **強制重新下載** — 卡在舊版時的逃生門。清掉 Service Worker 與所有快取，換一個帶時間戳的網址重載，繞過每一層快取。打卡紀錄存在 localStorage，不受影響

**改 `sw.js` 以外的檔案時，記得把 `sw.js` 裡的 `CACHE` 版號 +1**。Service Worker 是靠自己的檔案內容有沒有變來判斷要不要更新的，只改 `app.js` 而沒動 `sw.js` 的話，裝置不會知道有新版。

## 資料存在哪

- **打卡紀錄**存在瀏覽器的 localStorage，畫面永遠讀它 → 點下去零延遲，離線照常用
- 同步只是背景的事。Firebase 掛掉、網路不通、SDK 載不下來，App 一樣能打卡，等連上線自動補傳
- Firestore 結構：
  - `families/{配對碼}/meta/profile` — 設定與作息項目
  - `families/{配對碼}/records/{YYYY-MM-DD}` — 一天一筆、每項獨立欄位，所以兩台裝置改同一天的不同項目不會互相蓋掉
  - `families/{配對碼}/bonuses/{id}` — 特別獎勵一筆一份文件，兩台同時給獎也不衝突
  - `families/{配對碼}/quizzes/{YYYY-MM-DD}` — 當天過了哪幾關、挑戰幾次、拿了幾點，一天一份文件
- 點數一律由紀錄即時算出，不另外存總分，資料不會對不上

### 衝突怎麼處理

每次連上伺服器會先**對帳**：本機有、雲端沒有的資料補上去，之後才以雲端為準。三個集合（打卡紀錄、特別獎勵、闖關成績）都會對帳。

順序很重要 —— 如果先套用雲端資料，這台離線期間累積的紀錄會在對帳讀到它們之前就被洗掉。

也不能只在「雲端全空」時才上傳：裝置可能離線好幾天累積了新資料，而雲端已經有舊的，那樣新資料就永遠傳不上去。

整體偏向**「絕不弄丟任何一個爪印」**：

- 兩台裝置離線各自打卡 → 上線後取聯集，兩邊的都留著
- 家長在 A 取消某一項，B 當時離線且還記著舊的完成狀態 → B 上線後那一項會被補回來

第二點是第一點的代價。對貼紙表來說，寧可多一個章也不要少一個。等真的對上伺服器之後，取消就會正常傳到其他裝置。

「清除所有紀錄」會連雲端一起刪，不然下次同步又會整個長回來。

### 改作息表不會改寫歷史

打卡時會把「那天當時應該完成幾項」寫進該日紀錄（`_expected`）。判斷全破獎勵時用的是這個數字，不是現在的作息表。

沒有這層的話，家長新增一個項目就會讓過去每一個全破日失去 5 點獎勵，連續天數也會斷掉 —— 小朋友什麼都沒做，累積的爪印卻自己變少。

同理，已經蓋過的爪印永久有效，就算那個項目後來被刪掉也不會被扣回去。舊資料沒有 `_expected` 的話會退回用現行設定推算。

紀錄裡以底線開頭的欄位都是中繼資料，不是完成項目，統計時會排除。

### 安全性（老實說）

沒有帳號密碼，**配對碼就是鑰匙**。規則保證要「已登入 + 知道完整的 16 位配對碼」才能存取，而且不准列出所有家庭，所以外人猜不到。

但這也表示：**配對碼外流 = 資料外流**。不要貼到公開的地方，也不要拿這裡存任何敏感資訊。

`js/firebase-config.js` 裡的 `apiKey` 不是密碼 —— Firebase 網頁版的 apiKey 只是專案識別碼，本來就會出現在網頁原始碼裡，擋人的是安全規則。

備份：家長模式可以匯出一份 JSON。清除瀏覽器資料會刪掉本機紀錄（雲端那份還在，重新配對就會拉回來）。
